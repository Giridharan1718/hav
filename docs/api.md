# API contracts

Base path: `/api/v1` · Interactive docs: `/api/docs` · Machine-readable schema:
`/api/v1/openapi.json` (generated by FastAPI from the Pydantic models; there is no
hand-maintained duplicate).

## Conventions

- JSON in, JSON out. All request models reject unknown fields, so a client cannot
  mass-assign columns.
- Authentication is an opaque session in the `hva_session` cookie
  (`HttpOnly`, `SameSite=Lax`, `Secure` in production, 12-hour lifetime).
- Every unsafe request (`POST`/`PUT`/`PATCH`/`DELETE`) must send `X-CSRF-Token` equal
  to the `hva_csrf` cookie. The cookie is issued by `GET /auth/csrf`; the browser client
  obtains it automatically before the first mutation.
- `Origin` (or `Referer`) must match the configured app/API/CORS origins.
- Errors always use the same envelope; `request_id` is safe to quote in a support
  request and appears in structured server logs.

```json
{
  "error": {
    "code": "validation_error",
    "message": "One or more fields are invalid.",
    "details": [{ "field": "phone", "issue": "Enter a 10-digit Indian mobile number." }],
    "request_id": "0f3c…"
  }
}
```

- Rate limits are per endpoint and documented below; exceed them and you get `429` with
  `Retry-After`. The limiter is in-memory and therefore single-process (see
  [limitations](docs/limitations.md)).
- Pagination: `page` (≥1) and `page_size` (1–50) on search; responses include `total`,
  `page`, `page_size` and `pages`. Sorting is stable (`relevance`, `name`,
  `updated`, with slug as the tiebreaker).
- The API never submits applications, never certifies identity and never returns a
  benefit entitlement.

## Endpoints

`Auth` column: — public · C citizen session · R reviewer/admin with TOTP.

### Health and capability readout

| Method | Path | Auth | Limit | Purpose |
| --- | --- | --- | --- | --- |
| GET | `/health` | — | — | Liveness, database check, configured capability summary |
| GET | `/health/catalogue` | — | — | Published scheme count and the postal dataset's provenance and refresh time |

### Authentication and session

| Method | Path | Auth | Limit | Purpose |
| --- | --- | --- | --- | --- |
| GET | `/auth/csrf` | — | — | Issue the double-submit CSRF cookie |
| POST | `/auth/register` | — | 5/hour/IP | Create a citizen account and session (generic duplicate-email response) |
| POST | `/auth/login` | — | 10/15 min per email+IP | Password login; returns `mfa_required` for privileged accounts |
| POST | `/auth/mfa/verify` | challenge | 10/15 min/IP | Complete TOTP login challenge |
| POST | `/auth/logout` | C | — | Revoke this session and clear cookies |
| GET | `/auth/me` | optional | — | Current account, profile, address, consent and session summary |
| GET | `/auth/sessions` | C | — | List sessions; only a masked token fingerprint is returned |
| DELETE | `/auth/sessions/{id}` | C | — | Revoke one owned session |
| DELETE | `/auth/sessions` | C | — | Revoke all other sessions |
| POST | `/auth/password/change` | C | — | Change password, revoke other sessions |
| POST | `/auth/password/reset/request` | — | 5/hour/IP+email | Send a single-use reset link (same response for unknown emails) |
| POST | `/auth/password/reset/confirm` | — | 10/hour/IP | Consume the reset token |
| POST | `/auth/phone/challenge` | C | 5/hour/user | Send an OTP through the configured SMS adapter |
| POST | `/auth/phone/verify` | C | 10/hour/user | Verify OTP; marks phone access, not identity |
| POST | `/auth/mfa/setup` | C | — | Create a TOTP secret (encrypted) and provisioning URI |
| POST | `/auth/mfa/confirm` | C | — | Activate MFA after a valid code |
| POST | `/auth/reauth` | C | — | Password confirmation for sensitive actions |

Notable errors: `invalid_credentials` (generic), `mfa_required`, `mfa_invalid`,
`otp_expired`, `otp_locked`, `resend_cooldown`, `rate_limited`, `csrf_failed`,
`cross_origin_denied`.

### Postal lookup

| Method | Path | Auth | Limit | Purpose |
| --- | --- | --- | --- | --- |
| GET | `/postal/{pincode}` | — | 60/min/IP | Look up all post offices for a valid six-digit PIN |

Outcomes are explicit: `multiple_matches` (choose one), `not_found` (well-formed but
unknown), `invalid_format`, `provider_unavailable`, `stale_data`. The response carries
source provenance and last refresh time. A PIN never rewrites an address on its own.

### Scheme catalogue

| Method | Path | Auth | Limit | Purpose |
| --- | --- | --- | --- | --- |
| GET | `/schemes` | optional | 120/min | Search: `q`, `language`, `state`, `category`, `beneficiary`, `page`, `page_size`, `sort` |
| GET | `/schemes/meta/categories` | — | — | Category list, published count, supported languages |
| GET | `/schemes/{slug}` | optional | — | Detail with benefit, criteria, documents, steps, source, link check and rule summaries |
| GET | `/schemes/{slug}/eligibility/questions` | optional | — | Only the questions the current rules require, with purpose text |
| POST | `/schemes/{slug}/eligibility/evaluate` | optional | — | Deterministic result from submitted answers |
| GET | `/schemes/{slug}/checklist` | optional | — | Document checklist, optionally personalised by signed-in language |

Search results include `match.terms`, `match.reason`, `source_status`
(`draft`/`pending_review`/`source_checked`/`verified`/`rejected`/`superseded`),
`translation_available` and timestamps. Relevance explanations name only terms that
actually matched.

Eligibility request:

```json
{ "inputs": { "age": 62, "annual_income_inr": 90000, "state": "Delhi" } }
```

Response outcomes: `eligible`, `not_eligible`, `insufficient_information`,
`cannot_evaluate`. Unknown fields, out-of-range values and fields the rules do not
require are rejected with `422`. The response always includes a preliminary-result
disclaimer; answers are not stored.

### Assistant

| Method | Path | Auth | Limit | Purpose |
| --- | --- | --- | --- | --- |
| POST | `/assistant/messages` | optional | 30/hour/IP; signed-in users also have a daily quota | Grounded answer with citations, missing-information list, optional eligibility result |
| POST | `/assistant/transcribe` | C + voice consent | — | Transcribe base64 audio through the configured adapter; `503` when unconfigured |

Messages may be at most 1,000 characters; audio payloads are capped. A no-match query
returns an explicit no-match answer with no scheme citations. Provider output that
fails grounding validation is discarded and replaced by the deterministic composer.

### Drafts

| Method | Path | Auth | Limit | Purpose |
| --- | --- | --- | --- | --- |
| POST | `/drafts` | C | — | Create a draft; `reuse_profile: true` is required to copy stored profile fields |
| GET | `/drafts` | C | — | List the owner's drafts |
| GET | `/drafts/{id}` | C | — | Read one owned draft with field provenance |
| PATCH | `/drafts/{id}` | C | — | Update/remove/confirm fields; user edits are marked `user` |
| DELETE | `/drafts/{id}` | C | — | Soft-delete an owned draft |
| POST | `/drafts/{id}/export` | C + reauth not required | 10/hour/user | Produce a JSON/text draft document; requires `confirm: true`; `submitted` is always `false` |

Ownership is enforced server-side: another user's draft id returns `404`, not `403`, to
avoid confirming existence.

### Administration (TOTP required)

| Method | Path | Auth | Limit | Purpose |
| --- | --- | --- | --- | --- |
| GET | `/admin/review/queue` | R | — | Versions awaiting review, with pending translations and rule validation state |
| POST | `/admin/schemes/{version_id}/review` | R | 60/hour | Approve, reject, mark source-checked or supersede; reviewer identity and notes are recorded |
| GET | `/admin/audit` | R | — | Paginated audit events (no personal data in metadata) |
| POST | `/admin/ingestion` | R | 60/hour | Queue an approved-source fetch; returns `202` and a job id |
| GET | `/admin/ingestion/runs` | R | — | Ingestion runs with outcome and hashes |
| GET | `/admin/jobs` | R | — | Background job status |
| GET | `/admin/overview` | R | — | Counts and capability summary |

A citizen session, even with a valid CSRF token, receives `403` on these routes. A
reviewer without a completed TOTP challenge receives `403 mfa_required`.

## Example: anonymous search

```bash
curl -s 'http://127.0.0.1:8000/api/v1/schemes?q=farmer%20income&language=en&page_size=5' \
  | jq '.items[] | {name, official_url, source_status}'
```

## Example: authenticated mutation

```bash
# 1. Get cookies (session + CSRF) into a jar.
curl -s -c jar.txt http://127.0.0.1:8000/api/v1/auth/csrf >/dev/null

# 2. Register (or log in). The CSRF token is the cookie value.
#    Accepting the privacy notice is required; optional consents default to false.
CSRF=$(awk '$6=="hva_csrf" {print $7}' jar.txt)
curl -s -b jar.txt -c jar.txt -X POST http://127.0.0.1:8000/api/v1/auth/register \
  -H "Content-Type: application/json" -H "X-CSRF-Token: $CSRF" \
  -d '{"email":"demo@example.test","password":"correct horse battery","full_name":"Demo Person","preferred_language":"en","accept_privacy_notice":true}'
```

## Versioning and compatibility

`/api/v1` is the only supported version. Breaking changes require a new prefix; the
scheme detail payload's additive fields are safe to ignore. `docs/api.md` is updated in
the same change as any contract change, and the generated OpenAPI document is the
source of truth for field-level shapes.
